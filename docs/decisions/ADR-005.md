# ADR-005: DPO Preference Pair Quality Gate Threshold
Date: 2026-10-10
Status: Proposed

## Context

DPO (Direct Preference Optimization) converts correction events into permanent behavioral change by training Tier 2 on (prompt, chosen_response, rejected_response) pairs. The quality of these pairs directly determines whether the behavioral change is beneficial or corrupting. This is flagged as HIGH risk in ROADMAP.md:

> "DPO pair quality causing permanent corruption (HIGH): manual gate on 100%."

The quality gate is the human review step that determines whether a pair is safe to train on. The question is: what threshold makes a pair acceptable?

**Dimensions of quality to evaluate:**

1. **Clarity of preference:** Is the rejected response clearly worse for the stated reason? Ambiguous pairs ("both seem fine") create noisy training signal.
2. **Specificity:** Is the correction actionable? "Be more concise" is not specific; "stop repeating the same point in different words within a single answer" is.
3. **Generalizability:** Does the correction reflect a consistent preference, or a one-off context-specific reaction? (One-off reactions should not become permanent behavioral changes.)
4. **Contamination risk:** Does the rejected response contain factual content the chosen response omits? Training could suppress accurate information.
5. **Pair coherence:** Do both responses address the same prompt? Mismatched pairs corrupt the loss landscape.

**Proposed threshold options:**

| Option | Description | Risk |
|---|---|---|
| Accept all corrections | No gate | HIGH: noise and contamination enter training |
| Rate on binary scale (accept/reject) | Simple, fast | May accept ambiguous pairs |
| Rate on 1–5 scale, accept ≥ 4 | Higher bar | More rejections; slower pair accumulation |
| Structured checklist (all 5 dimensions pass/fail) | Highest quality | Slowest; risk of reviewer fatigue |

**Constraint:** Manual review of 100% of pairs is already decided (from ARCHITECTURE.md Section 4 Decided ADRs). The question is what the review protocol looks like.

## Consequences

- A high threshold (structured checklist) slows the DPO feedback loop but protects against silent corruption.
- A low threshold accelerates behavioral updates but risks permanently degrading Tier 2 on ambiguous signal.
- Regardless of threshold, a DPO behavioral regression test must run after every batch update.

## Risks

- **Small dataset risk:** With < 100 pairs, DPO is known to over-optimize. If pairs are slow to accumulate due to a strict gate, consider batching updates to minimum 50 pairs per DPO run.
- **Mode collapse:** DPO can cause mode collapse on responses the owner explicitly preferred, making Veena overly narrow. Track output diversity metrics alongside accuracy.
- **Reviewer fatigue:** If the quality gate is too complex, the owner will shortcut it. Design the review protocol to be completable in < 2 minutes per pair.
