# ADR-007: Capability Layer — Local vs Hybrid vs Frontier
Date: 2026-10-10
Status: Proposed

## Context

Veena's RELATIONSHIP layer (Tier 0, memory, sleep cycles) is well-specified. The CAPABILITY layer — the model that actually reasons, answers questions, and executes tasks — is an open architectural decision.

Three options:

**Option A: Pure local (Tier 1 = frozen local model)**
- All inference runs on owned hardware
- Maximum privacy: no data leaves the machine
- Capability ceiling: LLaMA 3.1 8B quality (competitive for routine tasks; inadequate for hard research-grade reasoning)
- Requires local GPU with sufficient VRAM (A100/H100 class for fast inference at 8B)
- Cost: hardware purchase (Phase 5 territory per current roadmap) or persistent cloud GPU rental

**Option B: Hybrid — local Tier 1 for personal/routine, frontier model for hard reasoning**
- Personal/context tasks (what are my goals, what am I working on, what pattern am I exhibiting) → local Tier 1
- Hard reasoning (research paper synthesis, code architecture review, complex scientific question) → frontier API (Claude, GPT-4, Gemini)
- Tier 0 context is filtered before leaving the machine — only what is necessary for the query is sent
- Privacy tradeoff: some context exits the machine; privacy policy and data retention of frontier provider applies
- Capability ceiling: frontier model quality for hard tasks (current state of the art)
- Cost: pay-per-query frontier API, which is variable and potentially expensive for heavy use

**Option C: Frontier-backed from the start (thin slice)**
- All inference routes to frontier API
- No local model in Phases 0–1; local model introduced when Phase 0 is complete
- Simplest to build; lowest infrastructure overhead
- Highest privacy risk; no cost ceiling

**Key tension:**
G2 (persistent corrections) and G4 (research application) require frontier-level capability. LLaMA 3.1 8B cannot reliably synthesize 40-page research papers or do multi-step scientific reasoning at the level needed. This is not a criticism of the local model — it is a capability fact, and pretending otherwise would violate the standing rule against flattery.

**Privacy architecture for hybrid:**
The session briefing proposes: "Tier 0 context filtered before leaving the machine." This requires a context filter layer that decides which personal facts are necessary for a given query and which are not. This layer does not yet exist and must be designed before hybrid can be safely deployed.

**Registered objection:** Hybrid with unfiltered Tier 0 context sent to frontier APIs is a serious privacy risk. Every goal, correction, behavioral pattern, and personal fact in Tier 0 would exit the machine on every hard query. This must be gated behind an explicit context filter that is designed and audited before hybrid goes live.

## Consequences

- **Pure local:** Limits G4 (research application) capability until hardware is purchased or cloud GPU is rented persistently.
- **Hybrid:** Enables G4 immediately; requires context filter design before deployment; adds API cost.
- **Frontier-backed:** Fastest path to G1 (usable early); requires local model work to begin on schedule or risks permanent API dependency.

## Risks

- **Hybrid privacy:** Context filter complexity is non-trivial. If it fails open (sends everything), sensitive personal data exits the machine silently.
- **API cost at scale:** Research-grade queries (long context, multi-step) are expensive. Budget alert at $50/month is already set; monitor against it.
- **Pure local capability gap:** If chosen, the owner must be honest that Veena will not match frontier capability for hard reasoning tasks. Tier 0 context will improve relevance but not reasoning quality.
