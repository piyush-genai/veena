# ADR-002: Tier 3 Vector Store — ChromaDB vs FAISS
Date: 2026-10-10
Status: Proposed

## Context

Tier 3 is the episodic buffer: a hard-capped (50,000 embeddings) vector store that persists interactions across sessions and feeds the MemMan classification pipeline and RAG retrieval. The vector store must:

- Persist across process restarts without manual export/import
- Support metadata filtering (sample_type, source, timestamp, tier0_refs)
- Enforce or cleanly respect a hard 50,000-embedding cap
- Integrate with LangGraph tool nodes
- Deliver p95 retrieval latency < 3 seconds (Phase 2 exit gate)
- Support cosine distance (required by MemMan similarity thresholds)

Two candidates:

**ChromaDB**
- Built-in persistence (SQLite/DuckDB backend, survives restart automatically)
- Metadata filtering is a first-class feature
- Simpler API: `collection.query(query_embeddings, where={...})`
- Slower than FAISS at scale; benchmarks suggest acceptable performance below ~100K vectors
- Direct LangChain/LangGraph integration available
- Hard cap must be enforced at application layer (no built-in limit)

**FAISS**
- Faster similarity search (especially at scale with IVF indexes)
- No built-in persistence — requires manual serialize/deserialize on every process stop/start
- No built-in metadata store — requires a parallel SQLite/Postgres store keyed to vector IDs
- More complex integration: higher operational burden for a solo developer
- LangChain wrapper exists but adds abstraction overhead

At 50,000 embeddings with all-MiniLM-L6-v2 (384-dim), the performance difference is marginal. The persistence and metadata complexity of FAISS becomes the dominant factor.

Outstanding question: at the 45,000-embedding eviction threshold, does ChromaDB's metadata-filtered eviction query (find lowest-value REDUNDANT samples) perform acceptably? This can only be benchmarked empirically.

## Risks

- **ChromaDB:** Hard cap enforcement is application-layer only — a bug in MemMan can silently exceed 50K. Require explicit cap check on every insert.
- **FAISS:** Persistence complexity creates a real risk of buffer loss on unexpected process termination. Would require a write-ahead log or checkpoint strategy.
- **Either:** The embedding model (all-MiniLM-L6-v2) must be benchmarked against alternatives before committing — retrieval quality at the cosine similarity thresholds MemMan uses (0.7, 0.85) depends on the embedding model, not just the vector store.
